## Codebase Patterns
- Workspace uses `version.workspace = true` etc. for shared package metadata
- `bunpo` is a local workspace crate (deinflection engine) used by jmdict-fast
- jmdict-fast build.rs copies pre-generated data from dist/ to OUT_DIR (no longer reads JSON)
- xtask caching uses project-level .cache/ directory (found by walking up to workspace root)
- Dict types (Entry, KanjiEntry, etc.) are duplicated: lib.rs (Deserialize only) and xtask/src/dict.rs (Serialize+Deserialize for generation)
- build.rs skips regeneration if OUT_DIR already has generated files
- Use `anyhow` for error handling in xtask; library will get typed errors later
- build.rs copies data from dist/ to OUT_DIR; rerun triggered by `cargo:rerun-if-changed=../dist`
- `cargo xtask generate` outputs to dist/ by default (configurable with --output flag)
- entries.bin header: magic `JMDF` (4) + u32 version (4) + u16-prefixed jmdict_version + u16-prefixed generated_at, then entry_count; header_size is dynamic
- MAGIC/FORMAT_VERSION constants must stay in sync between lib.rs and xtask
- After changing entries.bin format, `cargo clean -p jmdict-fast` is needed to clear cached OUT_DIR files
- `embedded` feature gates include_bytes; without it, build.rs is a no-op and Dict loads from filesystem
- Tests run from subdirectory — use `env!("CARGO_MANIFEST_DIR")` for compile-time workspace-relative paths
- `serde_json::Value` does NOT round-trip through postcard — use typed structs instead
- jmdict-fast uses `JmdictError` (in src/error.rs) for typed errors — all public methods return `Result<T, JmdictError>`
- JMdict xrefs (related/antonym) are `Vec<Vec<Value>>` in JSON with mixed string/number elements; convert to typed `Xref` struct during generation
- xtask dict.rs has Raw* types for JSON deserialization and typed Entry/SenseEntry for postcard serialization
- All lookup methods return Vec<LookupResult> (not Vec<Entry>) — access entry via .entry field
- bunpo CandidateWord.reason_chains is Vec<Vec<Reason>> — use Debug format for string conversion
- Dict lookup internals split into `*_candidates()` (FST search → Vec<MatchCandidate>) and `candidates_to_results()` (deserialize); enables lazy iteration
- QueryBuilder uses `_inner` private methods — public convenience methods (lookup_exact, etc.) wrap these
- `dict.lookup(term)` returns QueryBuilder; chain `.mode()` then `.execute()` for builder-style queries
- fst `levenshtein` feature must be enabled for fuzzy search; `Levenshtein::new(term, distance)` returns Result
- JMdict POS values are abbreviated codes: "v1" (ichidan verb), "vt" (transitive), "n" (noun), "adj-i" (i-adjective), etc. — NOT full words
